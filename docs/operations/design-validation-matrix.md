# Design Validation Matrix

AP-101 inventories the design surfaces that VA Auto-Pilot claims to support and
maps each one to an executable proof path. A design is not considered validated
by prose alone: each row below has either a concrete command/test entrypoint or
an explicit follow-up task that must close the runtime gap.

## Baseline Gates

Run these before claiming the matrix is current:

```bash
npm run typecheck
npm run check:all
npm run check:e2e
```

For public narrative and release-readiness rows, also run the stale wording scan
from `docs/operations/public-narrative-spec.md` and
`docs/operations/open-source-readiness-checklist.md` through
`npm run check:public-narrative`.

## Backlog Coverage

- AP-102: governed orchestrated dogfood run.
- AP-103: CI parity, release/manual gates, and public scan policy. Closed by
  `docs/operations/ci-parity.md`, `npm run check:public-narrative`, and CI
  typecheck coverage.
- AP-104: real observability/evidence bundle proof. Closed by runtime task
  events, per-task bundle materialization, and CLI flow assertions in
  `orchestrate-cli.yaml` and `cycle-restart.yaml`.
- AP-105: governance checkpoints plus permission scope runtime proof. Closed by
  stale checkpoint runtime flows for sprint-state/human-board/git-head drift
  and permission enforcement for prompt injection, out-of-scope diffs, and
  destructive command blocking.
- AP-106: budget guardrails plus eval/quality history runtime proof. Closed by
  loop CLI flows for budget soft/hard cycle limits and runtime eval
  PASS/FAIL/AMBIGUOUS history.
- AP-107: MCP resources plus smoke-test runner proof.

Rows without a follow-up task already have deterministic commands included in
`npm run check:all`, `npm run check:e2e`, or an explicitly documented release
scan. If that changes, add a backlog item before marking the affected design
validated.
